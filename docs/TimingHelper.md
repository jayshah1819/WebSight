# Memory Leak Detector

**Source:** `src/03-memory-leak-detector.js`
**Singleton:** `memoryLeakDetector` (created in `src/06-init-logging.js`, used by Modules 10 and 11)

---

## What This Does

WebGPU does not automatically free resources.

If you forget to call `.destroy()` on a `GPUBuffer` or `GPUTexture`, it stays allocated until the device is lost. Over time, that can quietly eat hundreds of MB of memory.

The Memory Leak Detector:

* Tracks every `GPUBuffer` and `GPUTexture`
* Detects resources that live longer than a configurable threshold
* Maintains running totals (current memory, peak memory, total allocated, total freed)
* Produces structured reports for debugging

By default, any resource alive longer than **60 seconds** is flagged as a potential leak.

---

## How Tracking Works

Module 10 (`10-webgpu-hooks.js`) intercepts resource creation and destruction.

### On creation

```js
device.createBuffer(desc)
  → memoryLeakDetector.trackResource(buffer, 'GPUBuffer', desc.size)

device.createTexture(desc)
  → memoryLeakDetector.trackResource(texture, 'GPUTexture', estimatedSize)
```

### On destroy

```js
buffer.destroy()
  → memoryLeakDetector.markDestroyed(buffer)

texture.destroy()
  → memoryLeakDetector.markDestroyed(texture)
```

That’s it. No polling, no proxies — just lifecycle interception.

### TimingHelper exclusion

Internal profiler buffers are excluded:

```js
if (label.startsWith("TimingHelper")) skip
```

Profiler overhead never appears in leak reports.

---

## Internal Design

### 1. `#resourceIds` (WeakMap)

```js
WeakMap<GPUObject, integer>
```

Instead of writing properties onto GPU objects, we store IDs in a private `WeakMap`.

Why?

* Avoids property collisions
* Doesn’t interfere with `__websight_id`
* Allows GC when the object becomes unreachable

The WeakMap gives us reverse lookup without holding strong references.

---

### 2. `resources` (Map)

```js
Map<integer, metadata>
```

This stores metadata only — **never the GPU object itself**.

Each entry looks like:

```js
{
  type: 'GPUBuffer' | 'GPUTexture',
  size: number,          // bytes
  createdAt: number,     // Date.now()
  destroyed: boolean,
  destroyedAt?: number,
  lifetime?: number,     // ms
  label: string,
  stack?: string         // optional
}
```

We intentionally avoid storing the actual resource object to prevent blocking garbage collection.

---

## Leak Detection Logic

Everything flows through a single private method:

```
#findLeaks()
```

Both `checkForLeaks()` and `getLeakReport()` call it.

That guarantees:

* One source of truth
* Consistent threshold logic
* `stats.leakCount` always matches report output

### What it does

For each tracked resource:

```
age = now - createdAt
```

Then classifies:

* `age > leakThreshold` → **leaks**
* `destroyed === false` and under threshold → **active**
* `destroyed === true` → **destroyed**

Results are sorted for usability:

* Leaks → largest first
* Active → largest first
* Destroyed → longest lifetime first (top 100)

---

## Automatic Map Pruning

Destroyed entries aren’t kept forever.

Every 100 `markDestroyed()` calls:

* Entries destroyed more than 60 seconds ago are removed
* This keeps long profiling sessions bounded in memory

Without pruning, thousands of short-lived buffers could accumulate metadata indefinitely.

---

## API Reference (Cleaner Overview)

### `trackResource(resource, type, size)`

Registers a resource.

* Safe to call twice (prevents double-counting)
* Returns the assigned internal ID

---

### `markDestroyed(resource)`

Marks a resource as freed.

Updates:

* `totalFreed`
* `currentMemory`
* `destroyedCount`
* `lifetime`

Safe to call on untracked objects (no-op).

---

### `checkForLeaks()`

* Runs detection
* Logs `console.warn`
* Displays `console.table`
* Warns if `currentMemory` exceeds `sizeThreshold`

This is a **diagnostic helper**, not required for report generation.

---

### `getLeakReport()`

Returns structured data without logging:

```js
{
  stats: { ... },
  leaks:     [...],
  active:    [...],
  destroyed: [...],
  summary:   { ... }
}
```

Use this for dashboards or exporting analysis.

---

### `enableAutoCheck(intervalMs = 30000)`

Runs `checkForLeaks()` periodically.

Example:

```js
memoryLeakDetector.enableAutoCheck();        // 30s
memoryLeakDetector.enableAutoCheck(120000);  // 2 minutes
```

Not enabled by default.

---

### `disableAutoCheck()`

Stops periodic checking.

---

### `formatBytes(bytes)`

Returns:

```
"0 B"
"1.50 KB"
"256.00 MB"
```

This is the single formatting source used across:

* `getMemoryStats`
* `getBufferData`
* public API helpers

---

### `formatTime(ms)`

Returns:

```
"500ms"
"3.2s"
"1.5min"
```

---

## Configuration

### `leakThreshold` (default: 60,000 ms)

If a resource lives longer than this, it’s considered a leak.

```js
WebSight.configure({ leakThresholdMs: 180000 });
```

Useful for long regression runs.

---

### `sizeThreshold` (default: 100 MB)

If `currentMemory` exceeds this:

* `checkForLeaks()` emits an additional warning

Example:

```js
memoryLeakDetector.sizeThreshold = 512 * 1024 * 1024;
```

---

### `captureStacks` (default: false)

When enabled:

* A JS stack trace is captured at `trackResource()` time
* Stack appears only in leak entries

Enable via:

```js
WebSight.configure({ captureStacks: true });
```

This has overhead — use only when debugging.

---

## Public API Integration

| WebSight API                     | Calls                                 |
| -------------------------------- | ------------------------------------- |
| `getMemoryLeaks()`               | `checkForLeaks()` → `getLeakReport()` |
| `getMemoryStats()`               | Returns `memoryLeakDetector.stats`    |
| `getFullAnalysisReport()`        | Includes leak report                  |
| `configure({ leakThresholdMs })` | Updates threshold                     |
| `formatBytes()`                  | Delegates                             |
| `formatTime()`                   | Delegates                             |

The detector is internal, but fully surfaced through WebSight.

---

## Known Limitations

| Scenario                                | Behavior                                |
| --------------------------------------- | --------------------------------------- |
| Resources created before WebSight loads | Not tracked                             |
| WebWorker / OffscreenCanvas WebGPU      | Not tracked                             |
| Samplers / Pipelines                    | Not tracked                             |
| Canvas swapchain textures               | Appear as leaks (browser owns lifetime) |
| Device lost                             | All live resources appear as leaks      |

These are trade-offs, not bugs.

---

## Data Flow (Simplified)

```
createBuffer / createTexture
        ↓
trackResource()
        ↓
resources Map  ←→  WeakMap reverse lookup
        ↓
#findLeaks()
        ↓
checkForLeaks()   getLeakReport()
        ↓
Public API
```

---

## Why This Design Works

* Zero polling
* No strong references to GPU objects
* Accurate running memory totals
* Bounded metadata growth
* Stack traces only when explicitly enabled
* Works transparently with normal WebGPU code

The detector does one thing:

> Track GPU resource lifetime and surface suspicious allocations.

Everything else — reporting, dashboards, summaries — builds on that core.
